# Part 5 Wiki＋原文 RAG：中文召回与附录状态复测（存档）

日期：2026-11-18（Asia/Hong_Kong）。本报告沿用原来的 16 题、32 个金标准事实和评分规则，记录第三轮真实模型运行。语义评分由 Codex 辅助复核，尚无独立人工签署。

## 结论

**本轮解决了这组问题中的中文命名空间召回、Part 5 范围误匹配和 Annex C 状态漏答，并使 Wiki 能带出与问题相关的规范原文。**

相对上一轮引用标签与预算修复，两组有原文引用支撑的事实覆盖均从 **26/32 提升到 31.5/32（98.4%）**，全部关键事实均有原文支撑的题数均从 **9/14 提升到 13/14**。Q03、Q13、Q14 由不完整或缺原文变为完整规范回答，Q06 的条目规则本轮也完整答出。Q02 仍把脚注数字当作成员名称后缀。

本轮两组共 32 条模型响应，全部通过引用格式及标签成员校验；267 项来源检查、118 个去重 HTTP 内容目标全部通过。193 项测试通过。前端和 HTTP API 实现未改动；规范原文、15 个 Wiki 内容页、题集和 FTS 索引均未改动。

**这不能证明混合检索比纯原文 RAG 更准确。** 两组正向题得分相同，共享的召回修复也改善了纯原文组。混合组能把 Wiki 关联的规范段落实际放入上下文并引用，解决了此前“只有草稿解释、没有原文确认”的问题。

## 本轮改动

### 中文召回与精确匹配

在原有检索路径中加入一个小型双语术语表：命名空间、会话、缓存、索引、诊断、范围、附录分别展开为对应英文检索词。保留用户原问题，原文 FTS、Wiki 排序和来源排序共用此展开；没有增加模型翻译调用或新依赖。

章节匹配先排除 `Part 5`／`第5部分` 这类文档编号，避免 Q13 被当作第 5 章查询。显式 `Annex C`／`附录 C` 可定位附录；对应 FTS 查询约束在该附录内。

原搜索结果现在区分实际精确命中与 FTS 命中。旧逻辑把 FTS 返回的章节／表格也当作精确命中，导致排名靠前的附录开头被后续表格挤到末尾；本轮保留 FTS 自身排序。

### Wiki 带出规范原文

旧 Wiki 排序的正文命中分数上限容易使多个页面同分。本轮在既有本地关键词检索上按词在页面中的稀有程度加权，继续优先标题和章节标题。

每个入选 Wiki 页面从其已验证的来源链接中，依据问题与原文／关联段落的相关性，选择最多两个规范范围。即使常规检索已有原文，也会尝试带出这些来源；共享范围按 ID 去重，再按实际原文与问题的重合度排序。

原文来自经过版本、摘要和行号校验的规范文件，独立获得原文引用标签，保留带出它的 Wiki 路径。Wiki 草稿正文继续使用 Wiki 标签与 draft 状态。内部来源候选不直接暴露为新的 API 字段。

top_k=6 及原有 Wiki 配额不变；混合组通常最多两页 Wiki，因此最多额外带出四个原文单元。它们仍受同一个 12000 字符证据预算约束，排序在常规原文之后、Wiki 正文之前。Wiki 正文可能因预算被省略，其带出的原文仍可保留。

### 完整正文与附录定位

若同一章节的完整原文与其重复前缀同时出现，且完整章节本身能放入预算，优先尝试完整章节，防止重复前缀先占空间后丢失章节尾部。过大的章节仍可使用已有的 6000 字符索引块；本轮未新增原文截断。

章节正文块的来源定位先匹配实际正文，不再优先使用其关联表格。Annex C 状态证据现定位为 **Annex C，L5754–5805**，而非 Table C.1，L5789–5800；资料性、弃用和 shall 状态位于该正文范围开头。

上一轮的引用白名单、引用登记表、原文优先预算及严格校验继续保留。本轮没有新增模型重试、标签猜测替换或前端改动，也没有新增 Annex C Wiki 页面。
